A Billingóban minden számlaféle bizonylat (`document`): a számla, a díjbekérő, az előleg- és a végszámla, a piszkozat, a sztornó és a módosító számla is. A tárcában ezeket a `tarca.documents` kezeli, a nyugtákat a `tarca.receipts` ([Nyugták](/docs/nyugtak)).

```ts twoslash
import { createTarca } from 'tarcajs'

const tarca = createTarca()

const { document, created } = await tarca.documents.createOnce({
  vendorId: 'ORDER-1001',
  partner: {
    name: 'Vevő Kft.',
    address: { postCode: '1111', city: 'Budapest', address: 'Fő utca 1.' },
  },
  items: [{ name: 'Webfejlesztés', quantity: 10, unit: 'óra', netUnitPrice: 15_000, vat: 27 }],
})

console.log(document.invoiceNumber, document.grossTotal, created)
```

A számlát a Billingo állítja ki és sorszámozza. Éles profilon azonnal beküldi a NAV-nak, ezért kiállított számlát törölni nem lehet, csak sztornózni vagy módosító számlával helyesbíteni. Törölni csak piszkozatot lehet.

<Callout type="warning" title="Számlát ne küldj újra kézzel">
  A tárca a `POST /documents` kérést soha nem ismétli meg. Ha egy kiállítás hálózati hibával vagy
  időtúllépéssel ér véget, nem tudhatod, elkészült-e a számla. Webshopból és webhookból ezért a
  `createOnce()`-t használd a rendelésed azonosítójával: [Pontosan
  egyszer](/docs/alapok/pontosan-egyszer).
</Callout>

## Egy számla életútja

1. **Kiállítás.** A `create()` vagy a `createOnce()` megkeresi a számlatömböt és a partnert, majd elküldi a számlát. A Billingo sorszámot ad (`2026-1`), kiszámolja az összegeket, és éles profilon beküldi a NAV-nak.
2. **Kiküldés.** Ha a `sendEmail` igaz, a Billingo maga küldi ki. Később a `send()` bármelyik címre elküldi.
3. **Fizetés.** Átutalásos számlánál a befizetést a `payments.add()` rögzíti, a `paymentStatus` ettől lesz `partially_paid`, majd `paid`.
4. **Javítás.** Hibás számlát a `cancel()` érvénytelenít, vagy a `createModification()` helyesbít. Módosító számla után a Billingo a sztornót elutasítja, ezért előbb dönts, melyik utat választod.

A díjbekérő és az előleg külön utat jár be: a [Díjbekérő](/docs/bizonylatok/dijbekero) és az [Előleg- és végszámla](/docs/bizonylatok/elolegszamla) oldal írja le.

## Amit élőben mértünk

- Ismeretlen vagy törölt azonosítóra a Billingo 403-at ad (`forbidden`), nem 404-et. Ismeretlen `vendorId`-ra viszont 404-et, ezért a [Lekérés](/docs/bizonylatok/lekeres) a `findByVendorId()`-t ajánlja.
- A lista később konzisztens: egy friss számla 15–30 másodperc múlva jelent meg benne.
- A piszkozat véglegesítése 201-et ad, a spec 200-at ír. A befizetések törlése 200 `[]`, az útmutató 204-et ír.
- A sztornó metódusa `POST`. Az útmutatóban szereplő `PUT` 405-öt ad.

A teljes lista: [Élő eltérések](/docs/alapok/eles-elteresek).
