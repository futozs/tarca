---

A `tarcajs/payments` a fizetési szolgáltató értesítéséből Billingo bizonylatot állít ki, a szolgáltató SDK-ja nélkül. A webhookkezelő ellenőrzi az aláírást, egységes `PaymentEvent` alakra hozza az eseményt, és átadja az `onPayment` függvényednek. Ott az `issueForPayment()` eldönti, hogy nyugta vagy számla jár, és pontosan egyszer kiállítja.

<Example slug="fizetesbol-bizonylat" />

A bizonylat `vendorId`-ja a fizetés azonosítójából képződik (`STRIPE-pi_3QhB7c`). Az újraküldött esemény ezért a meglévő bizonylatot kapja vissza (`created: false`), második kiállító kérés nem megy ki.

## Hogyan áll össze

1. A szolgáltató POST kérést küld a webhook címedre. A kezelő (`stripeWebhook`, `simplePayWebhook` …) a nyers törzsön ellenőrzi az aláírást. Hamis vagy hibás kérésre 400-at ad, az `onPayment` nem fut.
2. A kezelő a szolgáltató eseményéből `PaymentEvent`-et készít. Ha kell, lekéri a szolgáltató API-jából a hiányzó részleteket (tételek, vevő, az eredeti rendelés).
3. Az `onPayment` megkapja az eseményt. Itt hívod az `issueForPayment(tarca, payment, options)` függvényt.
4. Ha az `onPayment` hibát dob, a válasz 500, és a szolgáltató később újraküldi az eseményt. Mivel a kiállítás a `createOnce`-ra épül, az újraküldés nem állít ki második bizonylatot.

```ts twoslash title="app/api/stripe/webhook/route.ts"
import { createTarca } from 'tarcajs'
import { issueForPayment } from 'tarcajs/payments'
import { stripeWebhook } from 'tarcajs/payments/stripe'

const tarca = createTarca()

export const POST = stripeWebhook({
  secret: process.env.STRIPE_WEBHOOK_SECRET ?? '',
  onPayment: (payment) => issueForPayment(tarca, payment, { vat: 27 }),
})
```

## Szolgáltatók

| Szolgáltató | Belépési pont | Hitelesség | Fizetés azonosítója (`id`) |
| --- | --- | --- | --- |
| [Stripe](/docs/fizetesek/stripe) | `tarcajs/payments/stripe` | `Stripe-Signature`, HMAC-SHA256 | a Payment Intent (`pi_…`) |
| [SimplePay](/docs/fizetesek/simplepay) | `tarcajs/payments/simplepay` | `Signature`, HMAC-SHA384, kereskedőnként saját kulccsal | a SimplePay tranzakció |
| [Barion](/docs/fizetesek/barion) | `tarcajs/payments/barion` | nincs aláírás: a tárca a `PaymentState` végpontból olvassa ki az állapotot | a `PaymentId` |
| [Revolut](/docs/fizetesek/revolut) | `tarcajs/payments/revolut` | `Revolut-Signature`, 5 perces időablakkal | a rendelés (visszatérítésnél az eredeti rendelés) |
| [PayPal](/docs/fizetesek/paypal) | `tarcajs/payments/paypal` | a PayPal `verify-webhook-signature` végpontja | a capture |

Mind az öt ugyanazt a `PaymentEvent` alakot adja, ugyanazokkal a [közös beállításokkal](/docs/fizetesek/webhook-beallitasok). Saját szolgáltatónál magad is összerakhatsz egy `PaymentEvent`-et, és átadhatod az `issueForPayment()`-nek.

## Az esemény fajtái

| `kind` | Mit csinál az `issueForPayment()`? |
| --- | --- |
| `paid` | Nyugtát vagy számlát állít ki, lásd [Bizonylat a fizetésből](/docs/fizetesek/bizonylat-fizetesbol). |
| `refunded` | Sztornózza a bizonylatot, lásd [Visszatérítés](/docs/fizetesek/visszaterites). |
| `partially-refunded` | Visszatérítésenként egy módosító számlát állít ki, vagy javaslatot ad, lásd [Részleges visszatérítés](/docs/fizetesek/reszleges-visszaterites). |
| `refund-failed` | Nem ír semmit, jelzi, hogy a már kiállított sztornót vagy módosítót kézzel kell rendezni (csak Stripe). |
| `failed`, `other` | Kihagyja (`kind: 'skipped'`). |

<Callout type="warning" title="Ne nyeld le a hibát az onPayment-ben">
  Ha a kiállítás nem sikerül, hagyd, hogy a webhook 500-at adjon: a szolgáltató újraküldi az
  eseményt, a `createOnce` pedig a meglévő bizonylatot adja vissza. Kivétel a `validation` hiba
  (hiányzó áfakulcs, eltérő összeg), mert az újraküldéstől nem javul: ezt jelezd embernek. A
  `refund-proposal` nem hiba, hanem eredmény, de szintén emberi döntést kér.
</Callout>
