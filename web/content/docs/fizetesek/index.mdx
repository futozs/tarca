A `tarcajs/payments` a fizetési szolgáltató SDK-ja nélkül dolgozik. A webhookkezelő ellenőrzi az aláírást, az `issueForPayment()` eldönti, hogy nyugta vagy számla jár, és pontosan egyszer kiállítja a Billingóban. A bizonylat `vendorId`-ja a fizetés azonosítója, ezért az újraküldött esemény a meglévő bizonylatot adja vissza.

## Nyugta vagy számla

- Számla jár, ha a vevő adószámot adott meg, ha az összeg eléri a 900 000 Ft-ot, vagy ha a vevő számlát kér; egyébként nyugta. Pénztárgép-köteles tevékenységnél (`cashRegisterRequired`) validációs hibát kapsz. A `document: 'invoice'` vagy `'receipt'` felülírja a döntést.
- Számlánál a vevőből partner lesz: magyar adószámmal `HAS_TAX_NUMBER`, EU-s vagy külföldi adószámmal `FOREIGN`, magánszemélyként `NO_TAX_NUMBER`.
- A számlát a tárca fizetettnek jelöli, a nyugta eleve fizetett.
- Áfát a tárca nem talál ki: `vat`, `vatFor` vagy tételenkénti áfakulcs nélkül validációs hibát ad, kérés nélkül. A tételek bruttó összegének fillérre egyeznie kell a fizetett összeggel.

## Stripe webhook

<Example slug="stripe-webhook" />

A Stripe-ban a `checkout.session.completed`, a `checkout.session.async_payment_succeeded`, a `charge.refunded` és a `charge.refund.updated` eseményre iratkozz fel. Hibás aláírásra 400 a válasz, és az `onPayment` nem fut. Ha az `onPayment` dob, 500, és a Stripe később újraküldi. Egy teljes Next.js útvonal: [Stripe webhook recept](/docs/receptek/stripe-webhook).

## Visszatérítés

<Example slug="visszaterites" />

- Teljes visszatérítéskor a tárca egyszer sztornózza a bizonylatot. Azt, hogy a sztornó megtörtént-e, a bizonylat `cancelled` jelzője dönti el, bizonytalan hiba után is.
- Részleges visszatérítéskor számlánál visszatérítésenként egy módosító számla készül. Ehhez `setIfAbsent`-et ismerő tároló kell (`ledger`), mert a Billingo módosító számlájának nincs `vendorId`-ja. `ledger` nélkül a tárca javaslatot ad (`refund-proposal`), bizonylatot nem állít ki.
- Nyugtánál részleges visszatérítésre mindig javaslat jön, mert nyugtához a Billingo nem ad módosító bizonylatot.

## A többi szolgáltató

```ts twoslash
import { createTarca } from 'tarcajs'
import { issueForPayment } from 'tarcajs/payments'
import { simplePayWebhook } from 'tarcajs/payments/simplepay'

const tarca = createTarca()

export const POST = simplePayWebhook({
  merchants: {
    HUFKERESKEDO: process.env.SIMPLEPAY_SECRET_HUF ?? '',
  },
  onPayment: (payment) => issueForPayment(tarca, payment, { vat: 27 }),
})
```

| Szolgáltató | Belépési pont | Aláírás |
| --- | --- | --- |
| Stripe | `tarcajs/payments/stripe` | `Stripe-Signature`, HMAC-SHA256 |
| SimplePay | `tarcajs/payments/simplepay` | HMAC-SHA384, kereskedőnként saját kulccsal |
| Barion | `tarcajs/payments/barion` | Nincs: a tárca a `PaymentState` végpontból olvassa ki az állapotot |
| Revolut | `tarcajs/payments/revolut` | `Revolut-Signature`, 5 perces időablakkal |
| PayPal | `tarcajs/payments/paypal` | A PayPal `verify-webhook-signature` végpontja |

Mind ugyanazt a `PaymentEvent` alakot adja. Az összeg `{ value, minor, currency }`, ahol a `minor` egész szám a pénznem váltóegységében, így minden összevetés kerekítés nélkül megy.
